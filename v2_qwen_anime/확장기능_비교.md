# 1차 직접 작성 프롬프트와 2차 확장 기능 프롬프트 비교 (2026-10-29)

1차 45장은 Claude 가 컨셉 시트를 읽고 프롬프트를 직접 썼고, 2차 45장은 같은 내용을 메인 허브의 프롬프트 확장 기능(`qwen3.8:27b`, 메타 규칙 + 코드 검사)에 넣어 나온 프롬프트로 그렸다.
아래 숫자는 모두 이 폴더의 `final_v2.json`(최종 PNG 에서 꺼낸 실제 입력)과 1차 프롬프트를 비교해 잰 값이다.

## 1. 같은 것과 다른 것

| 항목 | 1차 (직접 작성) | 2차 (확장 기능) |
|---|---|---|
| 생성 모델 | Z-Image Turbo (8 steps, cfg 1) | Qwen-Image-2512 (30 steps, cfg 4) |
| 편집 모델 | Qwen-Image-Edit-2511 | 같음 |
| 그림체 | 2000년대 초 손그림 판타지 장편 애니메이션 | 2010년대 후반 일본 극장판 애니메이션 + TV 애니 셀화 머리말 |
| 캐릭터 설명·컷 구성 | 컨셉 시트에서 직접 작성 | 1차와 같은 문장을 확장 기능의 입력으로 넣음 |
| 프롬프트 모양 | 고정 틀: 구도 → 캐릭터 블록 → 핵심 디자인 → 배경 → 그림체 | 확장 기능이 한 문단으로 다시 씀, 그림체 문장은 코드가 끝에 붙임 |

- 캐릭터 설명과 컷 구성을 1차와 똑같이 넣었으므로, 프롬프트 차이는 확장 기능이 다시 쓴 결과다.
- 모델도 바뀌었으므로, 그림의 차이를 모두 프롬프트 탓으로 볼 수는 없다.

## 2. 확장 기능이 바꾼 점 (잰 값)

| 항목 | 1차 | 2차 |
|---|---|---|
| 평균 길이 (그림체 문장 제외) | 182 단어 (116~315) | 166 단어 (110~229) |
| 160 단어를 넘는 컷 | 정하지 않음 | 24 / 45 |
| 부정어(no, not, without)가 있는 컷 | 29 / 45 | 2 / 45 |
| 조명·카메라·배경·질감 네 항목 | 컷마다 다름 | 45 / 45 모두 포함 (코드 검사) |
| 최종 규칙 통과 | 해당 없음 | 38 / 45 |

- 부정문은 거의 사라졌다.
  - 예: 1차 "no fingers are visible" → 2차 "the cuffs closed and drooping" 처럼 보이는 모습으로 바뀜
- 조명·카메라·배경·질감은 모든 컷에 들어갔다.
  - 예: 표정 시트에도 "soft diffused studio lighting, frontal medium close-up" 같은 구절이 붙음
- 같은 캐릭터 설명이 컷마다 다른 문장으로 다시 쓰여, 1차처럼 '글자 그대로 반복' 은 아니게 됐다.
  - 예: 퀼린스 3·4번은 같은 설명을 서로 다른 순서와 표현으로 씀

## 3. 확장 기능에서 나온 문제

### 규칙끼리 부딪침

- '사용자 말을 그대로 지켜라(주제 유지)' 와 '손 단어를 빼라(손 숨김)' 가 부딪쳐, 니키 2·4번은 3회 고쳐 쓰기 뒤에도 위반이 남았다.
  - 예: 캐릭터 설명의 "completely cover both hands, so no fingers are visible" 를 지키면 손 단어 규칙을 어김
- 손 단어를 피하려고 엉뚱한 말을 만들었다.
  - 예: 니키 1번 "completely cover the extremities (팔다리 끝을 덮음)"
- 손 숨김 규칙의 예시 문장을 상관없는 곳에 붙였다.
  - 예: 일리아 4번 "the ribbon tucked inside the drooping sleeve cuff and propped against the shoulder"
- 캐릭터 설명이 길면 '160 단어 이내' 와 '설명을 모두 지켜라' 가 부딪쳐, 설명 일부가 빠지거나 길이를 넘었다.
  - 예: 푸토르 5번 첫 확장은 249 단어에 지킬 말 6개가 빠짐 (다시 확장해 통과)

### 고장

- 베스 4번 첫 확장은 477 단어로, 뒤쪽이 같은 낱말을 쉼표로 되풀이하는 낱말 나열이 됐다 (다시 확장해 178 단어로 통과).
- 이름이 바뀌었다.
  - 예: 퀼린스 1·3번 "Quillins" → "Quilins"
- 45컷 중 27컷이 '그림체 말은 넣지 말라' 는 지시에도 그림체 문장의 구절을 본문에 다시 넣었다.
  - 예: "polished digital cel shading", "cool blue-violet shadows" 가 본문과 끝 문장에 두 번 들어감

### 코드 검사가 놓친 것

- 니키가 손님으로 나오는 세 장면(일리아 4, 일로케 4, 일루키 4)은 손 숨김 요청을 알아보지 못해 손 단어 검사가 돌지 않았다.
  - 예: "dangling over her hands so that her hands stay hidden" 은 검사식이 찾는 "손 … 숨김 … 소매" 순서가 아님
- 부정문을 긍정문으로 바꾸면서 '없어야 할 것' 이 사라졌다.
  - 예: 퀼린스 5번 입력의 "no face in the picture" 가 빠져, 얼굴을 그려 넣은 후보가 두 번 나옴

| 퀼린스 5번에 얼굴이 나옴 | 위의 부정문 소실 + 머리말의 "anime-style faces" | r1 원본(손만 나옴)을 편집으로 애니풍으로 바꿈 |

## 5. 정리

- 확장 기능은 부정문을 없애고, 네 가지 시각 요소를 빠짐없이 넣는 일은 잘했다.
- 길고 정해진 캐릭터 설명을 여러 컷에 똑같이 유지하는 일은 1차의 직접 작성 방식이 더 안정적이었다.
- 손 숨김, 나이, 피부색처럼 모델이 세게 받거나 무시하는 특징은 두 방식 모두 결국 편집으로 고쳤다.
